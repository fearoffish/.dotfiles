# Commits

## Before committing

- Inspect `git diff` and keep it focused.
- Never commit to `main`, `master` or `trunk`. Branch from `origin/HEAD` with a
  relevant name; replace an autogenerated branch name before its first commit.
- Follow repository naming conventions. Otherwise omit category prefixes from
  branch names (`fix/`, `chore/`).
- Prefer amending an existing commit for related fixes; update its message
  rather than adding a follow-up commit.

## Message format

- Use Conventional Commit prefixes in subjects (`fix:`, `feat:`, `refactor:`,
  `chore:`) where one fits.
- Subject under 51 characters, excluding the prefix.
- When a body is useful, use a dash list with lines under 73 characters focused
  on why; wrap filenames, code and identifiers in backticks.
- UK spelling, no Oxford commas.

## Mechanics

- Use real newlines, not literal `\n`; pass multiline messages through
  `git commit -F -` with a heredoc.
- Do not add agent `Co-Authored-By` lines or GPG-sign agent commits; pass
  `-c commit.gpgsign=false` when committing.
- Never `git push`. Pushing is always done by hand.

## Examples

```
fix: stop wiping the Dock on first apply

- `persistent-apps -array` cleared every pinned app, which is
  destructive on an existing machine and unhelpful on a new one
- `static-only` already hides anything that is not running
```

```
refactor: drop Linux support

- every machine is now a Mac, so the dual-OS abstraction only
  added branches that could never be exercised or tested
- rendered `.gitconfig` and `config.fish` are byte-identical
```

```
chore: regenerate Brewfile from installed state
```
